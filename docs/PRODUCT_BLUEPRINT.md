# Invariant product blueprint

Invariant verifies whether completed application workflows preserve business rules. Kane CLI drives the actual browser and extracts state. Invariant defines contracts, checks evidence and evaluates relationships. Codex is intended to implement authorized repairs in a later phase.

## Phase 1

LedgerLab is a controlled local demonstration. It exposes two accounts with predictable starting balances, a transfer form, a success confirmation, a history with stable transaction IDs, retry and reset. The corrected ledger and two independently labeled seeded defects are served on separate routes.

Conservation compares the combined balance before and after a successful transfer. Idempotency compares both balances and the successful transaction count across a retry of the same transaction. Non-negative balances, refund reversibility and failed-transfer atomicity have catalog entries for later work.

Evidence separates workflow completion, usable observations, deterministic verdict, and repair authorization. Failed or incomplete browser runs leave the invariant inconclusive.

## Later phases

1. Bound Codex repair to approved implementation files. Record the code diff and revision, preserve the contract and browser objective, and run the same verification before and after the change. Enforce retry and credit limits.
2. Build the developer dashboard with contract browsing, execution timelines, state transitions, violation analysis, repair history and exportable evidence receipts.
3. Package reusable contract configuration, CLI tooling, onboarding and a reproducible benchmark.

The hackathon weighs shipping, verification, closed loop and craft equally. Verification and closed loop are the stated tie-breakers.
