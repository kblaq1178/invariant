# Repair security model

The host owns the contract, evaluator, browser objective, evidence, patch gate, and loopback server. A fresh temporary Codex workspace contains only the seeded transaction source. The host derives that source from the existing conservation fixture and shared ledger definitions. The corrected implementation and original repository stay outside the agent workspace. The page uses the served transaction module for state updates, while the presentation and money parsing are host-owned.

## Enforcement and validation

- Phase 2 uses an explicit Codex permission profile. It makes the disposable workspace writable, denies access to the original repository and the configured credential directories, and disables command network access. The Codex client still uses its configured sign-in for inference. The agent runs with approval policy `never`, ephemeral sessions, ignored user configuration, no configured web search, and no inherited environment for model-generated shell commands.
- The production path probes the native sandbox before launching Kane. The probe checks an actual read of the corrected implementation is denied and the disposable file can be opened for update. The same permission settings are passed to `codex exec`. On Windows the default is explicit MXC. On hosts where it is unavailable, the operator can select the explicit elevated backend and must pass the same probe.
- The elevated Windows backend requires general filesystem read access and enforces the explicit deny paths. Other OS-readable paths can remain readable depending on the backend and host policy. The probe establishes the tested accesses under the native command sandbox. It is not a comprehensive penetration test or an assertion about unrelated files.
- The operating system permits writes in the temporary workspace. The host only accepts a change in `transactions.ts`, checks the full workspace inventory, rejects additions, deletions, links and unexpected file types, and compares protected hashes. The candidate gate also holds the rest of the source fixed, reviews the changed transfer operations, and tests ledger state and error behavior before serving the candidate. These gates detect unsupported changes. Filesystem enforcement is provided separately by the Codex sandbox.
- The benchmark limits accepted transfer syntax to existing local state operations. The local behavior checks run with fresh inputs and a short VM deadline. The trusted browser host serves the candidate only as a browser module under a constrained content security policy. The VM and browser policy are additional controls for this benchmark, not general-purpose untrusted-code isolation.
- Each live run holds the same lock used by Phase 1B, reuses the 240-second Kane timeout and 300-second watchdog, records charges after completion, and stops on missing evidence, budget exhaustion, or a rejected patch. Private raw streams, packets, and reported changes are kept under the ignored runtime directory. Local hashes link evidence to receipts without proving authenticity against an administrator who can replace both.

A refused preflight stops before spending Kane credits. Rejected candidates are never served. The server closes at the end, the temporary workspace is never reused, and a lone regular candidate file is restored to its baseline. If unexpected filesystem entries prevent a safe reset, the workspace stays quarantined from the application and the private record identifies it for inspection.
